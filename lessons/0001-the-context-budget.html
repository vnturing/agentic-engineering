The context budget

Mission: direct coding agents so the output stays reviewable, without losing your own skills. First, the agent’s side of the ledger.

1. What an agent is

A working definition, from Simon Willison’s guide: a coding agent is an LLM that can run code and uses tools in a loop until a goal is met. Anthropic uses nearly the same definition for agents in general.

flowchart LR
  G[Your goal] --> L[LLM]
  L -->|tool call| T[Tools: read file, run tests, grep]
  T -->|output appended| C[(Context)]
  C --> L

Look at the arrow into Context. Every file the agent reads and every command output lands in that same window, and the model rereads it all each turn. Nothing leaves unless you or the tool removes it.

2. The context is a budget, not a bucket

Anthropic’s framing: models have a finite attention budget, so the job is to find the smallest set of high-signal tokens that makes the desired outcome likely. Bigger windows don’t remove the problem.

The evidence: Chroma’s Context Rot report tested 18 models and found performance grows less reliable as input length grows, even on simple tasks. Two honest caveats: the tasks are synthetic, and the authors don’t explain the mechanism.

Anthropic’s own Claude Code guidance builds nearly everything on one constraint: the window fills fast and performance degrades as it fills.

3. Three levers you control

Reset. Clear the session between unrelated tasks so old noise isn’t carried along.
Delegate. Send investigation to a subagent: it explores in its own context and returns a summary, so your main session stays clean.
Verify. Give the agent a check it can run (tests, build, screenshot). Without one, you become the only feedback loop.

A fourth, subtler lever: keep standing instructions lean. An ETH Zurich study of AGENTS.md files found they gave no improvement in task success while raising inference cost by over 20%, because agents follow them faithfully, doing extra exploration and testing. Short, non-redundant files are the takeaway, not “never write one.”
